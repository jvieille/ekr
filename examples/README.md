# Examples and Implementation Cases

**Status: Example — non-normative**

This area is for examples, implementation experience and cases used to test EKR Architectural Guidance.

Examples can help reveal whether a proposed distinction, requirement or pattern is useful, too weak, too heavy, incomplete or already well served by an established approach.

An example does **not**:

- define EKR;
- become a reference implementation by inclusion;
- make a product, technology or architecture canonical;
- prove that a Guidance proposition is universally correct.

Examples should state their context, objectives, assumptions, constraints, evidence and limitations clearly.

Examples may be added progressively. Publication in this area does not change the status of the canonical Working Definition or of any Guidance artefact.


Implementation experience should normally enter through the [Implementation experience / case Issue form](https://github.com/jvieille/ekr/issues/new/choose) before a durable example artefact is added here.
